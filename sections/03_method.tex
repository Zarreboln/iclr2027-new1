\section{Method}
\label{sec:method}
Place recognition is retrieval: given a query image, we search a database $\mathcal{D}$ of geo-tagged images and return the place of the best match. Comparing every candidate patch by patch is too slow on millions of images, so we work in two stages. Stage 1 gives each image one global descriptor, obtained by weighted second-order pooling of its patch features, and scans the database with it. Stage 2 re-ranks the shortlist by matching patches directly. One frozen forward pass per image supplies everything both stages need.


\subsection{Tokens}
\label{sec:prelim}
Each image passes through a frozen DINOv2/DINOv3 backbone, and we keep the value facet of one block \citep{vitfacets,effovpr}. A PCA is fitted across patch tokens collected from a few hundred unlabelled database images and then applied to every token, reducing it to $C{=}512$ channels. Tokens are $\ell_2$-normalized, so an image becomes $N$ unit vectors $\mathbf f_1,\dots,\mathbf f_N$. Two similarities follow: $G_{ij}=\mathbf f_i^{\top}\mathbf f_j$ inside one image, and $S_{ij}=\mathbf q_i^{\top}\mathbf d_j$ between a query and a candidate. Appendix~\ref{app:hyper} sweeps the block, the facet and the shortlist depth.

\subsection{The weight}
\label{sec:feat}
Sky, pavement and a facade of identical windows fill an image with near-copies of the same content. We want ten nearly identical sky patches to contribute about as much as one unique patch, rather than ten times as much, so each patch is weighted before either stage uses it.

For token $i$, we want the total weight of the tokens similar to it to be about constant:
\begin{equation}\label{eq:demo}
  \sum_j G_{ij}\,w_j = 1,
  \qquad\text{in matrix form}\qquad
  G\mathbf w=\mathbf 1,
\end{equation}
the democratic-weighting condition of \citet{democratic} and \citet{gmp}. We impose it on the thresholded table $\hat G_{ij}=\mathbb 1[\,G_{ij}>\tau\,]$, which counts near-copies rather than grading them, and the condition then solves in closed form:
\begin{equation}\label{eq:weight}
  w_i=\frac{1}{n_i},
  \qquad
  n_i=\sum_j \hat G_{ij}.
\end{equation}
A patch that recurs twenty times in its image receives one twentieth of the weight of a patch that occurs once. Appendix~\ref{app:ridge} gives the derivation. The threshold $\tau$ is the only constant here, fixed at $0.5$ everywhere.

\subsection{First stage}
\label{sec:global}
Stage 1 needs one fixed-size descriptor per image so that the database can be searched by inner product.

Take a patch $\mathbf q$ from the query and a patch $\mathbf d$ from a candidate. Squaring their similarity gives $(\mathbf q^{\top}\mathbf d)^2=\langle\,\mathbf q\mathbf q^{\top},\ \mathbf d\mathbf d^{\top}\,\rangle$: a comparison of two matrices, each built from one image alone. Summing over all patch pairs therefore collapses into a single comparison between two per-image matrices,
\begin{equation}\label{eq:so-deriv}
  \sum_{i,j} w_{Q,i}\,w_{D,j}\,\big(\mathbf q_i^{\top}\mathbf d_j\big)^{2}
  =\big\langle\, G_C(Q),\ G_C(D)\,\big\rangle,
  \qquad
  G_C(F)=\frac{1}{\sum_i w_i}\sum_i w_i\,\mathbf f_i\mathbf f_i^{\top}.
\end{equation}
$G_C$ records how an image's features co-occur across channels, ignoring where in the frame they appeared, and it keeps much more of the image than an average of the same tokens would (Appendix~\ref{app:coarsegrid}). Appendix~\ref{app:factorize} treats other powers.

We store $G_C$ flattened, take the square root of each entry, and $\ell_2$-normalize:
\begin{equation}\label{eq:stage1}
  \psi(F)\;=\;\frac{\rho\big(\operatorname{vec}(G_C(F))\big)}{\lVert\rho\big(\operatorname{vec}(G_C(F))\big)\rVert_2},
  \qquad
  \rho(u)=\operatorname{sign}(u)\sqrt{|u|}.
\end{equation}
This is the power normalization of \citet{improvedfisher}, standard for Fisher vectors and VLAD. It serves the weight's purpose one step later: a repeated element makes a few entries very large, and those entries would otherwise dominate the comparison. A whitened PCA then reduces the descriptor to $2048$ dimensions and the scan returns $P{=}\min(1000,|\mathcal{D}|)$ candidates. The same weight decides what to store, each image keeping its $1024$ highest-weight patches (\S\ref{sec:stage1abl}). Both PCAs are fitted on the deployment database and nothing else is fitted at all.

\subsection{Second stage}
\label{sec:core}
For each query patch we find its most similar patch in the candidate image and add up those similarities:
\begin{equation}\label{eq:stage2}
  s(Q,D)=\sum_{i=1}^{N_Q} w_{Q,i}\;\mathbb 1[\,m_i>\theta\,]\;m_i,
  \qquad
  m_i=\max_{j} S_{ij},
\end{equation}
the \textsc{MaxSim} rule of \citet{colbert}, weighted as in \S\ref{sec:feat}. Sky, pedestrians and occluders have no counterpart in the other image, so a patch counts only if its best match clears a confidence threshold $\theta$, fixed at $0.65$ everywhere (Appendix~\ref{app:calib}).

\textsc{MaxSim} cannot be written as an inner product of two fixed-size descriptors (Appendix~\ref{app:nofactor}), which is why it runs pair by pair on the shortlist rather than over the database, and why a method holding one vector per image cannot use it at all: such a method has to train its pooling until that single vector separates places on its own \citep{netvlad}. Our rule appears in the tables as \textsc{selfw\_conf}; a variant \textsc{mnn\_selfw65} also requires matches to be mutual and counts weighted inliers. Figure~\ref{fig:vis-m1} draws the surviving matches, and Appendix~\ref{app:effo-matched} compares both against \textsc{EffoVPR}'s attention-selected rule on an identical shortlist.
