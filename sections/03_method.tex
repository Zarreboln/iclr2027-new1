\section{Method}
\label{sec:method}
Every quantity in the pipeline is read off one table, the patch-to-patch similarity $S(A,B)=AB^{\top}$ between two sets of tokens from a single frozen forward pass. Read on an image against itself, $S(F,F)$, its thresholded row sums give each patch an importance $w$, which discounts repeated content such as sky or a facade of identical windows (\S\ref{sec:feat}). Read on a query against a candidate, $S(Q,D)$, it is reduced in two ways. A weighted sum of its squared entries factorizes into one descriptor per image and therefore scans the whole database (\S\ref{sec:global}); a weighted sum of its row maxima keeps the patch correspondences, does not factorize, and therefore re-ranks a shortlist (\S\ref{sec:core}). Both reductions use the same $w$, and the two stages differ only in how much of $S$ they keep.

\subsection{Preliminaries}
\label{sec:prelim}
A query image $I_q$ is matched against a database $\mathcal{D}=\{(I_d,\mathbf c_d)\}$ of images with known coordinates, and the coordinates of the retrieved image are returned as the query's. Every image is a grid of $N$ patches and passes once through a frozen DINOv2/DINOv3 backbone, from which we keep the value facet of one block, the output of its value projection \citep{vitfacets,effovpr}. A PCA fitted on database tokens reduces every token to $C{=}512$ channels; tokens are $\ell_2$-normalized. An image is therefore a matrix of $N$ unit vectors, $F=[\,\mathbf f_1,\dots,\mathbf f_N\,]^{\top}\in\mathbb R^{N\times C}$. For two such matrices we write $S(A,B)=AB^{\top}$, whose entry $S_{ij}=\mathbf a_i^{\top}\mathbf b_j$ is the cosine between patch $i$ of $A$ and patch $j$ of $B$. Two instances appear below: $S(F,F)$, an image against itself, and $S(Q,D)$, a query against a candidate. Appendix~\ref{app:hyper} sweeps the block, the facet and the shortlist depth.

\subsection{Patch importance from self-similarity}
\label{sec:feat}
Sky, pavement and a facade of identical windows fill an image with near-copies of the same content. We want ten nearly identical sky patches to contribute about as much as one unique patch, rather than ten times as much, so each patch receives an importance $w_i$ before either stage uses it. We ask that, for every token $i$, the total importance of the tokens similar to it be constant:
\begin{equation}\label{eq:demo}
  S(F,F)\,\mathbf w=\mathbf 1,
  \qquad\text{i.e.}\qquad
  \sum_j S(F,F)_{ij}\,w_j = 1\ \ \text{for all } i,
\end{equation}
the democratic-weighting condition of \citet{democratic} and \citet{gmp}. We impose it on the thresholded table $\hat S_{ij}=\mathbb 1[\,S(F,F)_{ij}>\tau\,]$, which counts near-copies rather than grading them. The condition then admits a closed-form solution,
\begin{equation}\label{eq:weight}
  \hat S\,\mathbf w=\mathbf 1
  \quad\Longrightarrow\quad
  w_i=\frac{1}{n_i},
  \qquad
  n_i=\sum_j \mathbb 1[\,S(F,F)_{ij}>\tau\,].
\end{equation}
A patch recurring twenty times in its image therefore receives one twentieth of the importance of a patch that occurs once (Figure~\ref{fig:blocks}). Appendix~\ref{app:ridge} gives the derivation.

\subsection{First stage \textcolor{red}{Chen: Coarse Ranking?}}
\label{sec:global}
{\color{blue}
Stage 1 scores a pair by adding up the similarity of every query patch to every candidate patch, that is, by summing over all entries of $S(Q,D)$. Computing that table for every database image would be far too slow, and it is not needed: the sum can be rearranged into an inner product of two vectors, one computed from the query alone and one from the candidate alone, so each database image is stored as a single fixed-size descriptor and searched as such. Take a patch $\mathbf q$ from the query and a patch $\mathbf d$ from a candidate. Squaring their similarity gives $(\mathbf q^{\top}\mathbf d)^2=\langle\,\mathbf q\mathbf q^{\top},\ \mathbf d\mathbf d^{\top}\,\rangle$: a comparison of two matrices, each built from one image alone. Summing over all patch pairs therefore collapses into a single comparison between two per-image matrices,
\begin{equation}\label{eq:so-deriv}
  \sum_{i,j} w_{Q,i}\,w_{D,j}\,S(Q,D)_{ij}^{2}
  =\big\langle\, G_C(Q),\ G_C(D)\,\big\rangle,
  \qquad
  G_C(F)=\frac{1}{\sum_i w_i}\sum_i w_i\,\mathbf f_i\mathbf f_i^{\top}.
\end{equation}
$G_C$ is the weighted second moment of the patch features: it records how an image's features co-occur across channels, ignoring where in the frame they appeared. The square is what makes it worth keeping. The same sum over the entries themselves, $\sum_{i,j}w_{Q,i}w_{D,j}S(Q,D)_{ij}$, is only the inner product of two weighted mean vectors, and an average of the same tokens retains far less of the image (Appendix~\ref{app:coarsegrid}). In kernel terms the stage is a degree-two polynomial match kernel over patches \citep{smk}, and it is exactly the case that factorizes; Appendix~\ref{app:factorize} treats other powers. The descriptor is flattened, $\ell_2$-normalized and whitened, and the database is scanned with it to a shortlist of $K$ candidates.
}

Stage 1 needs a fixed-size descriptor for each image so that all database images can be searched efficiently. We obtain it as the second moment of the patch features, each weighted by its importance $w_i$. Take a patch $\mathbf q$ from the query and a patch $\mathbf d$ from a candidate. Squaring their similarity gives $(\mathbf q^{\top}\mathbf d)^2=\langle\,\mathbf q\mathbf q^{\top},\ \mathbf d\mathbf d^{\top}\,\rangle$: a comparison of two matrices, each built from one image alone. Summing over all patch pairs therefore collapses into a single comparison between two per-image matrices,
\begin{equation}
  \sum_{i,j} w_{Q,i}\,w_{D,j}\,\big(\mathbf q_i^{\top}\mathbf d_j\big)^{2}
  =\big\langle\, G_C(Q),\ G_C(D)\,\big\rangle,
  \qquad
  G_C(F)=\frac{1}{\sum_i w_i}\sum_i w_i\,\mathbf f_i\mathbf f_i^{\top}.
\end{equation}
$G_C$ records how an image's features co-occur across channels, ignoring where in the frame they appeared, and it keeps much more of the image than an average of the same tokens would (Appendix~\ref{app:coarsegrid}). Appendix~\ref{app:factorize} treats other powers.

\subsection{Second stage \textcolor{red}{Chen: Fine Ranking?}}
\label{sec:core}
{\color{blue}
This stage reads $S(Q,D)$ row by row. For each query patch we find its most similar patch in the candidate image and add up those similarities,
\begin{equation}\label{eq:stage2}
  \sum_{i=1}^{N_Q} w_{Q,i}\;\mathbb 1[\,m_i>\theta\,]\;m_i
  = s(Q,D),
  \qquad
  m_i=\max_{j} S(Q,D)_{ij},
\end{equation}
the \textsc{MaxSim} interaction of \citet{colbert}, in which each query patch enters with the same importance $w_{Q,i}$ as in stage 1. Sky, pedestrians and occluders have no counterpart in the other image, so a patch counts only if its best match clears a confidence threshold $\theta$, fixed at $0.65$ everywhere (Appendix~\ref{app:calib}). The row maximum keeps which patch matched which, and for that reason it cannot be written as an inner product of two per-image vectors (Appendix~\ref{app:nofactor}); we therefore apply it only to the $K$ shortlisted candidates. A method that stores a single vector per image is thereby denied this stage, and must train its pooling until that vector separates places on its own \citep{netvlad}.
}
