\section{Method}
\label{sec:method}
As illustrated in Figure~\ref{fig:method}, the proposed method XXX follows a training-free paradigm and requires neither model training nor annotated data. All steps of the pipeline rely on a single patch-to-patch similarity (P2PS) strategy, expressed in three different forms. The query and the database images are first partitioned into patches, and their patch features are extracted by a frozen pretrained vision model. Based on these features, each image computes the similarity between its own patches (P2PS-1), from which the weight of every patch is derived (\S\ref{sec:feat}). Second-order pooling of the weighted patch features (P2PS-2) then yields one descriptor per image, with which the database is coarsely ranked, and patch-to-patch \textsc{MaxSim} matching between the query and the top-ranked database images (P2PS-3) refines this ranking (\S\ref{sec:coarse_to_fine_ranking}). Table~\ref{tab:readings} summarizes the three forms; the details are introduced below.

\subsection{Problem Formulation and Notation}  % CHEN-CHECK: his note asks for a new title; this is one option.
\label{sec:prelim}
The VPR task aims to find the location of a query image \citep{netvlad}. More specifically, given a query image $I_q$ and a database $\mathcal{D}=\{(I_d,\mathbf c_d)\}$ consisting of images $I_d$ and their spatial coordinates $\mathbf c_d$, VPR retrieves the database image that best matches the query, from which the query's coordinate $\hat{\mathbf c}_q$ is inferred. As discussed in \S\ref{sec:related}, most VPR solutions require a massive annotated training set $\mathcal{D}^{T}=\{(I_t,\mathbf c_t)\}$ to train a dedicated model for the classification and/or retrieval step. Training such a model takes from XX hours \citep{} to XX days \citep{}, depending on the complexity of the method and the scale of $\mathcal{D}^{T}$.  % CHEN-CHECK: numbers and citations still to be filled; see the note in the message.

The proposed XXX eliminates this training requirement by performing patch-similarity-based retrieval in a training-free manner. As shown in Figure~\ref{fig:method}, prior to retrieval, each input image $I$ (the query $I_q$ or any database image $I_d$) is partitioned into $N$ patches, $I=[\,p_1,\dots,p_N\,]$. A frozen vision encoder extracts a feature vector $\mathbf f_i\in\mathbb R^{C}$ for each patch $p_i$, so that every image is represented by a patch feature matrix $F=[\,\mathbf f_1,\dots,\mathbf f_N\,]^{\top}\in\mathbb R^{N\times C}$, where $C$ is the feature dimension. Following this notation, we denote the query's patch feature matrix by $Q$ and that of the $m$-th database image by $D_m$, $m=1,\dots,M$. Given these patch features, we adopt a general P2PS template,
\begin{equation}\label{eq:p2ps}
  S(A,B)=AB^{\top},
\end{equation}
where $A$ and $B$ are set to different patch feature matrices depending on the form of P2PS being applied. We first apply this template for patch weighting, and subsequently for coarse-to-fine ranking, as detailed below.

\subsection{Patch Weighting via Self-Similarity (P2PS-1)}
\label{sec:feat}
When comparing two similar images, humans naturally compare them patch by patch, and in doing so implicitly judge the importance of each patch by how often visually similar patches recur within the image. For example, patches of sky, pavement or grass appear nearly identical across many regions of the same image and are therefore perceived as less informative.  % CHEN-CHECK: an intuition, not an established finding; see the note.

In this paper, we capture this behaviour through a simple yet effective patch-to-patch self-similarity formulation (P2PS-1). Given the patch feature matrix $F\in\mathbb R^{N\times C}$ of an image, the P2PS template with $A=B=F$ gives $S(F,F)=FF^{\top}$, which is the Gram matrix $G\in\mathbb R^{N\times N}$ of $F$; its element $G_{ij}$, $i,j\in\{1,\dots,N\}$, is the similarity between patches $p_i$ and $p_j$. To count, for each patch, how many patches of the same image are highly similar to it, we introduce a similarity threshold $\tau$ and binarize the Gram matrix,
\begin{equation}\label{eq:demo}
  \hat G_{ij}=\mathbb 1\left[\,G_{ij}>\tau\,\right],
\end{equation}
where $\mathbb 1[\cdot]$ is the indicator function. The weight of patch $p_i$ is then defined as
\begin{equation}\label{eq:weight}
  w_i=\frac{1}{n_i},
  \qquad\text{where}\quad n_i=\sum_{j=1}^{N}\hat G_{ij},
\end{equation}
and $n_i$ counts the patches, including $p_i$ itself, that are highly similar to $p_i$, that is, the nonzero entries remaining in row $i$ of $\hat G$ after thresholding, as illustrated in Figure~\ref{fig:method}. Since $w_i$ is the reciprocal of $n_i$, a patch that recurs frequently across the image (large $n_i$) receives a small weight, while a distinctive patch with few or no similar patches (small $n_i$) receives a large weight, up to $w_i{=}1$, reflecting its higher importance (Figure~\ref{fig:blocks}). This weight is applied in the coarse-to-fine ranking described below.

\subsection{Coarse-to-Fine Ranking}
\label{sec:coarse_to_fine_ranking}
As discussed in \S\ref{sec:related}, VPR is essentially a retrieval task \citep{netvlad,anyloc}. We adopt the classical coarse-to-fine ranking pipeline \citep{patchnetvlad,r2former,selavpr}, and achieve highly competitive results even against methods trained on millions of annotated samples. More specifically, second-order pooling of the weighted patch features gives a coarse ranking, and patch-to-patch \textsc{MaxSim} matching gives the fine ranking.  % CHEN-CHECK: his green note says this repeats the overview; see the note.

\paragraph{Coarse Ranking (P2PS-2).}
\label{sec:global}
During coarse ranking, the query is compared with the whole database $\mathcal D$ to obtain the closest top-$K$ candidates, which requires a compact descriptor for every image. We obtain this descriptor by weighted second-order pooling of the patch features. Given the patch feature matrix $F$ of an image and its patch weights $\mathbf w=[w_1,\dots,w_N]$ from P2PS-1 \eqref{eq:weight}, the weighted patch features are aggregated into a $C\times C$ second-moment matrix,
\begin{equation}\label{eq:gc}
  G_C(F)=\frac{1}{\sum_i w_i}\sum_i w_i\,\mathbf f_i\mathbf f_i^{\top},
\end{equation}
in which patches with larger weight, that is, the more distinctive patches of \S\ref{sec:feat}, contribute more strongly. The similarity between the query and a database image is the inner product of their descriptors, which equals the weighted sum of squared P2PS entries between the two images,
\begin{equation}\label{eq:so-deriv}
  \big\langle\, G_C(Q),\ G_C(D_m)\,\big\rangle
  =\sum_{i,j} w_{Q,i}\,w_{D_m,j}\,S(Q,D_m)_{ij}^{2},
\end{equation}
since $(\mathbf q^{\top}\mathbf d)^{2}=\langle\mathbf q\mathbf q^{\top},\mathbf d\mathbf d^{\top}\rangle$ for any two patches. Hence the descriptor compares all pairs of patches between the two images without ever forming $S(Q,D_m)$ (Supplementary~\S\ref{app:coarsegrid} and~\S\ref{app:factorize}). As $G_C$ is high-dimensional, we follow \citep{bcnn,mpncov} and apply PCA to obtain a compact descriptor $\mathbf g=\rho(G_C)$ for efficient large-scale search.  % CHEN-CHECK: bcnn and mpncov are in the bib but not yet Scholar-checked.
Denoting the query and the $m$-th database descriptors by $\mathbf g_Q$ and $\mathbf g_{D_m}$, coarse ranking sorts all database images by $\mathbf g_Q^{\top}\mathbf g_{D_m}$, and the top-$K$ images are passed to fine ranking.

\paragraph{Fine Ranking (P2PS-3).}
\label{sec:core}
For each query patch we find its most similar patch in the candidate image and add up those similarities,
\begin{equation}\label{eq:stage2}
  s(Q,D_m)=\sum_{i=1}^{N} w_{Q,i}\;\mathbb 1[\,m_i>\theta\,]\;m_i,
  \qquad
  m_i=\max_{j} S(Q,D_m)_{ij},
\end{equation}
the sum of best matches introduced by chamfer matching for comparing two images \citep{chamfer} and known as \textsc{MaxSim} in late-interaction retrieval \citep{colbert}, weighted as in \S\ref{sec:feat}. Sky, pedestrians and occluders have no counterpart in the other image, so a patch counts only if its best match clears a confidence threshold $\theta$, fixed at $0.65$ everywhere (Supplementary~\S\ref{app:calib}). \textsc{MaxSim} cannot be represented by a single fixed-size descriptor per image, so we apply it only to the top-$K$ candidates (Supplementary~\S\ref{app:nofactor}). A method that stores a single vector per image is thereby denied this step, and must train its pooling until that vector separates places on its own \citep{netvlad}. The candidates are re-sorted by $s(Q,D_m)$, and the top one gives the query's location.
