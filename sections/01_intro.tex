Visual Place Recognition asks where a photograph was taken by retrieving the most similar image from a database of geo-tagged photographs, which may run to millions of images. We report Recall@$1$, the fraction of queries whose top return is a correct place. The question the field turns on is how an image should be represented so that similar places come out close together.

\paragraph{Supervision.} The field's default is to learn an aggregation layer on top of a frozen backbone from place labels, a template set by \citet{netvlad} and followed through classification over geographic cells \citep{cosplace,eigenplaces}, labels at scale \citep{gsvcities}, and pooling learned over frozen DINOv2 tokens \citep{salad,boq}. The corpus this asks for varies by an order of magnitude: about half a million street-level photographs across sixty thousand places for the GSV-Cities line \citep{gsvcities}, forty million and upward for the SF-XL line \citep{cosplace,eigenplaces} and for the methods that pool several sources \citep{megaloc,selavprpp}. What the supervision produces is also bound to the imagery it saw. Off that distribution the same methods lose a large part of their accuracy on the benchmark suite of \citet{anyloc}, and the layer is fitted to one backbone, so a stronger network is another corpus and another run before any of its strength reaches the ranking.

\paragraph{Training-free.} A second line keeps the pre-trained network fixed and asks only how to read it \citep{anyloc,segvlad,effovpr}. It pays none of the costs above, and the strongest of these methods decides which patches to keep from the class token's attention \citep{effovpr}. That attention is a by-product of pre-training on web imagery, where what deserves attention is the object in a photograph. It was never asked which parts of a scene identify a place, and the two questions have different answers: one window in a facade of identical windows is locally striking and is kept, yet it cannot tell this building from the next one like it, while a plain strip of pavement that occurs once may be the only thing in the frame that does. On street view the two answers happen to agree often enough that the substitution costs little. Away from street view they come apart and it becomes a liability: on a degraded corridor and on a subterranean set, weighting patches by attention scores below using no weight at all, while weighting each patch by how many of the image's own patches resemble it gains on both (\S\ref{sec:ood}). A larger backbone does not repair this, since it answers the pre-training question better rather than answering a different one.

\paragraph{Self-similarity.} We put that decision back inside the image. Each patch is weighted by how many of the image's own patches look like it. An element that fills much of the frame arrives as many similar patches, and dividing each of them by their number lets that element count once, the same as an element seen only once. This is the democratic-weighting condition of \citet{democratic} and \citet{gmp}, which on a thresholded table of patch similarities has a closed form (\S\ref{sec:feat}). Nothing is grouped or segmented along the way: patches that look alike need not sit together, so a facade of identical windows counts once rather than once per window. Where a compact index is wanted, the patches kept are the ones this weight ranks highest.

\paragraph{Cross-similarity.} That settles what a patch is worth. What remains is how two images compare, and the table between them is read twice. Summed bilinearly it collapses into one vector per image, so a whole database can be scanned by inner product. Taking each query patch's best match instead does not collapse, because a patch may find its match anywhere in the other image and no single vector can record where. The first reading is cheap and coarse, the second expensive and precise, and running the second only on the shortlist the first returns keeps the cost down. A method that stores one descriptor per image has the first alone, and has to train its pooling to make up for the second \citep{netvlad}. Keeping both is what lets the pipeline stay untrained.

We hereby present a VPR method that settles inside the image what that image contributes, giving every scene element one vote whatever its extent, and requiring no place label, external vocabulary or aggregation to train. Unlike a trained representation, which settles what counts with a place-labelled corpus, and unlike the frozen line, which hands that decision to a saliency head learned for another objective, ours takes it from the pair being matched and leaves the network untouched.

\noindent\textbf{Contributions.}
\begin{enumerate}[leftmargin=*,itemsep=1pt,topsep=3pt]
\item We identify two failure modes in VPR. A trained representation is fitted to a place-labelled corpus and loses a large part of its accuracy away from it. The strongest training-free method hands the choice of which patches count to the class token's attention, a by-product of pre-training on web imagery that was never asked which parts of a scene identify a place, and off street view that choice falls behind using no criterion at all.
\item We introduce a VPR pipeline carried by two tables of patch similarity. The self-similarity of one image weights each patch by how many of that image's own patches resemble it, in closed form; the cross-similarity of the pair is reduced two ways, one factoring into a per-image covariance that scans a database, the other not factoring and re-ranking a shortlist. No codebook, segmentation, learned saliency or place label is used.
\item We achieve the highest mean over thirteen benchmarks under one fixed configuration, match the strongest supervised baseline on the urban benchmarks its supervision targets, and improve published pipelines when our scoring rule replaces or is added to theirs.
\end{enumerate}
